## 摘要
检索增强生成（RAG）通过将生成依据建立在外部证据上，提高了大型语言模型（LLM）的回答质量，但处理检索到的上下文使预填充阶段成为主要的服务成本。RAG缓存融合通过重用为检索到的块预先计算的键值（KV）缓存，并在当前提示下选择性地重新计算令牌，来降低这一成本。然而，现有的选择器面临质量和效率之间的权衡：快速的查询无关或最后一层查询到上下文的选择器可能会遗漏与请求相关的证据，而全视图查询感知选择器在重新计算前需要广泛的上下文和层级可见性，从而阻塞了逐层缓存融合流程。我们提出了QCFuse，一种用于RAG缓存融合的压缩视图查询感知选择器。QCFuse利用块锚点查询探测，将用户查询状态条件化于紧凑的每块锚点，并通过关键层分析来识别需要重新计算的令牌，无需检查所有层。我们在SGLang中实现了QCFuse，并在六个数据集上对四个开源权重LLM进行了评估。QCFuse达到了完全预填充级别的质量。在同等质量下，QCFuse的平均预填充时间相比完全预填充加速了1.7倍，相比保留质量最强的基线ProphetKV加速了1.5倍。

## Abstract
Retrieval-augmented generation (RAG) improves large language model (LLM) answer quality by grounding generation in external evidence, but processing retrieved contexts makes the prefill stage a dominant serving cost. RAG cache fusion reduces this cost by reusing precomputed key-value (KV) caches for retrieved chunks and selectively recomputing tokens under the current prompt. Existing selectors, however, face a dilemma between quality and efficiency: fast query-agnostic or final-layer query-to-context selectors can miss request-relevant evidence, whereas full-view query-aware selectors require broad context and layer visibility before recomputation and therefore stall the layer-wise cache-fusion pipeline. We present QCFuse, a compressed-view query-aware selector for RAG cache fusion. QCFuse uses chunk-anchor query probing to condition user-query states on compact per-chunk anchors and critical-layer profiling to identify recomputation tokens without all-layer inspection. We implement QCFuse in SGLang and evaluate it on four open-weight LLMs across six datasets. QCFuse reaches full-prefill-level quality. At matched quality, QCFuse achieves an average prefill-time speedup of 1.7x over full prefill and 1.5x over ProphetKV, the strongest quality-preserving baseline.

## 1. 研究动机与核心问题
- **背景**：检索增强生成（RAG）通过将外部检索证据作为上下文提供给大型语言模型（LLM），提升回答质量。然而，处理检索到的长上下文导致**预填充阶段（prefill）成为服务延迟的主要瓶颈**（占总时间大头）。
- **现有方案**：RAG KV缓存融合技术通过复用预先计算好的块级KV缓存，并仅对部分token进行选择性重新计算，以减少预填充开销。
- **核心困境**：**选择器（决定哪些token需要重新计算）面临质量与效率的权衡**。
  - 快速选择器（如CacheBlend、EPIC、FusionRAG）忽略用户查询或因仅使用最后一层信号，可能遗漏关键证据。
  - 全视图查询感知选择器（如ProphetKV）利用全部层和全部上下文进行查询相关性评估，选择质量高，但需要加载大量KV缓存并分析所有层，**阻塞了层级流水线**，导致选择本身成为新的瓶颈。
- **论文目标**：设计一种**既保持查询感知的高质量，又不牺牲流水线效率**的选择器，解决“全视图”选择器造成的串行化和加载开销问题。

## 2. 方法论：QCFuse 核心设计
QCFuse 提出**压缩证据视图的查询感知选择器**，通过离线构建紧凑的token视图和层视图，使在线选择能快速完成，无缝融入层级流水线。

### 2.1 关键洞察
- **Token视图可压缩**：查询到上下文的注意力质量高度集中在少数token上。
- **层视图可压缩**：中间层的注意力信号最能近似全层选择结果，无需检查所有层。

### 2.2 核心组件
#### (1) 块锚点查询探测（Chunk-Anchor Query Probing，解决Token视图瓶颈）
- **离线阶段**：
  - 为每个语料块选取代表性的锚点token（使用KVzip方法，按token受关注程度排序，保留10%）。
  - 存储这些锚点的KV缓存作为紧凑的“锚点缓存”。
- **在线服务**：
  - 仅加载**锚点缓存**（而非完整上下文KV）来条件化用户查询，计算查询感知的隐藏状态。
  - 用该状态与**原始上下文的关键层key**计算注意力分数，对原始所有上下文token打分，选出需要重新计算的token集合 **P**。

#### (2) 关键层剖析（Critical-Layer Profiling，解决层视图瓶颈）
- **离线阶段**：
  - 在标注数据集（SQuAD等）上，衡量每一层单独定位答案证据的Recall@10%。
  - 选取**Recall最高的Top-3层**作为关键层集 **L★**。
- **在线服务**：
  - 选择器**仅使用关键层**的key缓存进行token评分，避免加载全部L层。
  - 显著减少传输量，使查询感知评分可与KV加载流水线重叠。

#### (3) 流水线集成
- 选择阶段仅需锚点KV和关键层key，耗时极短。
- 一旦 **P** 确定，启动稀疏重新计算内核（Triton优化），仅对P中token执行注意力和存储更新，并与后续层的KV加载重叠执行。
- 最终KV缓存：重算位置用新值，其余位置保留复用值。

### 2.3 公式化表示目标
目标为在资源约束下最大化证据覆盖：
- 选择集P满足：|P| = ⌊ρN⌋ （ρ为重算比例）
- 锚点token数：|C_A| ≤ r_a N （r_a=10%）
- 关键层数：|L★| = 3
- 选择时延远小于全视图选择。
