## 摘要
使用大型语言模型（LLMs）进行仓库级代码生成仍然具有挑战性，主要由于复杂的依赖关系和有限的上下文窗口。最近的方法采用检索增强生成（RAG）和规划机制来重用仓库中潜在的被调用函数。然而，这些方法通常存在两个局限性：在规划过程中缺乏测试驱动的行为指导，以及在重用过程中忽略了仓库代码中嵌入的实现逻辑。因此，生成的计划可能与预期行为不一致，检索到的函数可能无法被有效地重用。在本文中，我们提出了TICoder，一个新颖的仓库级代码生成框架，它改进了规划和重用两个方面。TICoder引入了一种测试驱动的迭代规划机制，该机制利用测试用例作为行为规范来细化实现步骤。此外，TICoder采用了一种实现感知的代码重用策略，该策略使用双视图相似性来检索潜在的被调用函数，该相似性同时捕获功能和实现方面。然后，我们通过一个结合基于结构的聚类和基于困惑度的过滤的双阶段选择策略来识别相关的使用模式。我们在广泛使用的仓库级代码生成基准上使用各种LLM进行了大量实验。实验结果表明，TICoder优于最先进的方法，平均提升了11.52%。

## Abstract
Repository-level code generation with Large Language Models (LLMs) remains challenging, primarily due to complex dependencies and limited context windows. Recent approaches adopt retrieval-augmented generation (RAG) and the planning mechanism to reuse potential callee functions in the repository. However, these approaches often suffer from two limitations: lack of test-driven behavioral guidance during planning and overlooking the implementation logic embedded in repository code during reuse. As a result, generated plans may not align with expected behaviors, and retrieved functions may not be effectively reused. In this paper, we propose TICoder, a novel repository-level code generation framework that improves both planning and reuse. TICoder introduces a test-driven iterative planning mechanism that leverages test cases as behavioral specifications to refine implementation steps. Furthermore, TICoder employs an implementation-aware code reuse strategy, which retrieves potential callee functions using a dual-view similarity that captures both functional and implementation aspects. We then identify relevant usage patterns through a dual-stage selection strategy, combining structure-based clustering and perplexity-based filtering. We conduct extensive experiments on widely used repository-level code generation benchmarks with various LLMs. Experimental results demonstrate that TICoder outperforms state-of-the-art (SOTA) methods, achieving an average improvement of 11.52%.

- **现有方法局限**：当前主流的规划+检索增强生成（RAG）方法虽然取得进展，但仍存在两个关键缺陷：
  - **L1：规划阶段缺乏测试驱动的行为指导**。仅从模糊的自然语言需求推导实现步骤，容易遗漏关键行为细节（如边缘情况、特定格式要求），导致计划不准确。
  - **L2：重用阶段缺乏代码级实现感知**。检索候选调用函数时只考虑语义相似性，忽略代码的实际执行逻辑，且不提供函数在仓库中的真实使用模式，导致检索不准、复用困难。
- **整体含义**：TICoder旨在通过将测试驱动开发理念融入规划过程，并引入兼顾功能与实现的双视角相似度以及使用模式筛选机制，从根本上提升仓库级代码生成的准确性和可靠性。

### 2. 论文提出的方法论：核心思想与技术细节

TICoder框架包含三个核心阶段：

- **阶段一：测试驱动的迭代规划**
  - **初始规划生成**：将需求`r`和测试用例`t`一起输入LLM（作为规划器），依据五项原则（清晰可验证、边界条件感知、显式依赖声明、可维护性、良好范围分解）生成初始实现步骤序列`s = {s_1,...,s_ns}`。
  - **迭代细化（法官-反思机制）**：
    - 引入另一个LLM（作为法官），从三个维度评估当前实现步骤：功能覆盖与一致性、独立性、粒度，每个维度打分0-100并给出文本理由。
    - 若任何维度低于预设阈值（90），法官将评估结果连同需求、测试用例、当前步骤一并反馈给规划器，由规划器重新生成步骤。
    - 重复该过程直到所有得分达标或达到最大迭代次数`n_i`，以此实现测试用例对规划过程的行为级引导。

- **阶段二：实现感知的代码重用**
  - **双视图被调用函数检索**：
    - **步骤感知的代码表示**：对每个实现步骤`s_i`，利用LLM生成对应的代码片段`c_i`。
    - **双视图相似度计算**：
      - *功能相似度*`Sim_F`：步骤嵌入`E_{s_i}`与仓库中函数描述嵌入`E_{d_j}`的余弦相似度。
      - *实现相似度*`Sim_I`：步骤代码嵌入`E_{c_i}`与仓库中函数实现嵌入`E_{f_j}`的余弦相似度。
      - 加权求和：`Sim(i,j) = α * Sim_F(i,j) + β * Sim_I(i,j)`，`α+β=1`。
    - 根据`Sim(i,j)`降序排序，为每个步骤选出最相关的被调用函数`fc_i`，形成`fc`集合。
  - **双阶段使用模式选择**：
    - **基于图的调用者识别**：利用LSP构建仓库调用图，找出每个`fc_i`的所有调用者函数作为候选使用模式。
    - **基于结构的模式聚类**：若两个调用者函数调用的函数集合完全相同，则归为同一簇，以保证多样性。
    - **基于困惑度的相关性过滤**：
      - 簇内过滤：每个簇内保留对需求`r`的条件困惑度`PPL(r|c)`最低的那个调用者作为簇中心。
      - 全局排序过滤：将所有簇中心按困惑度升序排列，选取前`n_p`个作为最终使用模式`fp_i`。

- **阶段三：增强的代码生成**
  - 将原始需求`r`、测试用例`t`、检索到的被调用函数`fc`以及筛选出的使用模式`fp`组合成提示，交由骨干LLM生成最终代码。
