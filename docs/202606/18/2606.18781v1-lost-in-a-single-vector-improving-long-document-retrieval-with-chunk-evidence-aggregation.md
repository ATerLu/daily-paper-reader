## 摘要
稠密检索将一个查询向量与一个文档向量进行排名。在长文档上，当在排名前文档编码过程中，一个短但关键的片段被弱化时，这种接口可能会失效。我们将这种失效模式作为文档侧早期压缩进行研究，并引入证据稀释指数（EDI）来衡量文档级表示与同一相关文档中最强块级证据之间的差距。基于这一视角，我们提出DICE（通过块证据的文档推理），一种无需训练的文档侧策略，该策略将文档分割成块，使用冻结模型独立编码，然后将它们聚合回单个向量，同时保持标准的一查询一文档接口。在LongEmbed上，DICE在四个骨干模型上提升了检索性能，在超过4k token的片段上增益最大：对于Dream，Passkey >4k从30.0提升至90.0，Needle >4k从23.3提升至74.0。在12,779个过滤样本中，DICE在92.8%的情况下实现了比单向量基线更低的EDI。这些结果确立了文档级编码作为长文档检索中一个实用且尚未充分探索的突破口。

## Abstract
Dense retrieval ranks one query vector against one document vector. On long documents, this interface can fail when a short but decisive span is weakened during document encoding before ranking. We study this failure mode as document-side early compression and introduce the Evidence Dilution Index (EDI) to measure how far a document-level representation falls below the strongest chunk-level evidence within the same gold document. Guided by this view, we propose DICE (Document Inference via Chunk Evidence), a training-free document-side strategy that splits documents into chunks, encodes them independently with a frozen model, and aggregates them back into a single vector while preserving the standard one-query-one-document interface. On LongEmbed, DICE improves retrieval across four backbones, with the largest gains on slices beyond 4k tokens: for Dream, Passkey >4k rises from 30.0 to 90.0 and Needle >4k from 23.3 to 74.0. Across 12,779 filtered samples, DICE yields lower EDI than the single-vector baseline in 92.8% of cases. These results establish document-level encoding as a practical and underexplored lever for long-document retrieval.

### 1. 论文的核心问题与整体含义

- **核心问题**：稠密检索（Dense Retrieval）在处理长文档时存在“文档侧早期压缩”的失效模式。当文档极长，而解答查询的关键证据仅占文档中极其简短的一小段时，直接对整个文档进行单向量编码，会导致这段决定性的证据在编码过程中被大量无关上下文稀释和弱化，从而在后续的查询-文档相似度排名中表现不佳。
- **整体含义**：该研究将上述直觉问题形式化为可度量的指标（证据稀释指数 EDI），并提出了一种实用且无需重新训练的解决方案（DICE），证明了在保持标准“一查询一文档”检索接口的前提下，通过改变文档侧的编码策略，是提升长文档检索性能的一个有效且尚未被充分探索的突破口。

### 2. 论文提出的方法论

- **核心思想**：延迟压缩（Delaying Compression）。通过先将文档分割成多个独立的块进行编码，保留局部的关键证据，然后再将这些块嵌入聚合成一个单一的文档向量，从而避免关键信息在处理整个长文档时被提前稀释。
- **关键技术细节（DICE 流程）**
    - **分块**：将长文档 $d$ 的 Token 序列分割成大小为 $k$ 的连续块，默认无重叠（$o=0$）。
    - **局部位置编码**：每个块 $d^{(j)}$ 被冻结的编码器 $f$ 独立编码。关键操作为**本地位置索引重置**，每个块内部的位置编码都从零开始，而非继承其在原文档中的绝对偏移量。这确保每个块被当作一个自包含的上下文窗口处理。
    - **聚合**：使用查询无关的聚合函数 $g$ 将所有块嵌入融合成最终的文档向量 $\mathbf{d}_{\text{DICE}}$。默认且最稳健的策略是**均值池化**（Mean Pooling）：$\mathbf{d}_{\text{DICE}} = \frac{1}{m} \sum_{j=1}^{m} \mathbf{h}_j$。
    - **检索接口不变**：查询编码和最终的相似度计算 $s(\mathbf{q}, \mathbf{d})$ 保持不变，整个改动完全位于文档编码侧。
- **诊断工具（EDI）**
    - **证据浓度（EC）**：$EC = \frac{m - \bar{a}}{|m| + \epsilon}$。其中 $m$ 是文档内最强的块级证据分数，$\bar{a}$ 是平均块相似度。EC用于衡量查询相关性是否高度集中于少数块。
    - **证据稀释指数（EDI）**：$EDI = \frac{m - s_E}{m - \bar{a} + \epsilon}$。其中 $s_E$ 是文档级相似度分数。EDI量化了文档级向量相较于最强块级证据的下降程度，数值越低表示稀释程度越小。

- **显著性能提升**：DICE在所有四个骨干模型上均改善了LongEmbed的整体平均分数，尤其在**长上下文片段（>4k tokens）上增益巨大**。例如，在Dream模型上，Passkey >4k 的 Hit@1 从 30.0 跃升至 90.0，Needle >4k 从 23.3 提升至 74.0。

- **机制验证**：DICE的性能增益与其系统性地**降低了EDI**相吻合。在92.8%的测试样本中，DICE的EDI低于单次向量基线，证明了其缓解证据稀释的核心假设是成立的。
- **质量-成本权衡**：DICE增加约3-4倍的文档侧编码计算量，但换取了在长文档检索上显著的准确性提升。考虑到文档索引通常离线完成，这在许多场景下是划算的。

### 7. 优点

- **严格保持检索接口**：完全保留了“一查询一文档”的标准稠密检索接口，无需修改成熟的索引和检索管道。
- **完全免训练**：策略简单，即插即用，可直接应用于任何已冻结的稠密检索模型，无需昂贵的微调或重新训练。
- **问题与分析框架新颖**：不仅提出了 DICE 方法，更构建了“文档侧早期压缩”的概念和 EDI 量化指标，为诊断和解决长文档检索问题提供了新的视角和工具。
- **实验验证全面扎实**：覆盖多种主流模型架构，通过详尽的消融实验和分层分析，清晰揭示了方法工作的内在机理。

### 8. 不足与局限

- **编码计算成本增加**：对同一文档进行多次独立编码，使得文档侧计算开销增大了约3-4倍，对实时性要求极高的在线编码场景可能构成挑战。
- **聚合的查询无关性**：融合块向量时未利用查询信息，失去了一次基于查询动态筛选关键块的机会，其性能理论上存在上限。
- **块大小配置需任务特定**：虽然在多数任务上块大小为1024表现最佳，但实验表明，最优块配置具有任务依赖性（如在FollowIR上表现不同），工业部署时可能需要针对特定场景进行验证。
- **保留单向量瓶颈**：最终仍将信息压缩至单一向量，与多向量或后期交互方法相比，不可避免地会丢失一部分细粒度的证据。
