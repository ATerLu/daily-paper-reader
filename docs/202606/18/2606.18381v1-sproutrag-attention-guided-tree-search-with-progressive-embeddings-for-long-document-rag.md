## 摘要
检索增强生成（RAG）系统必须在检索粒度与上下文连贯性之间取得平衡，现有方法通过LLM引导的分块、单层上下文扩展或分层摘要来应对这一挑战。这些方法不同程度地依赖索引或检索过程中昂贵的LLM调用，将上下文聚合限制在单一粒度层级，或通过摘要引入信息损失。我们提出SproutRAG，这是一种注意力引导的分层RAG框架，通过将句子级分块组织为语义连贯的渐进式更大单元，并利用学习到的句间注意力构建二叉分块树，来解决这一权衡。与依赖外部LLM、固定上下文扩展或有损摘要的先前方法不同，SproutRAG学习哪些注意力头与层最能捕捉语义文档结构，从而在无需额外LLM调用或压缩摘要的情况下实现多粒度检索。在检索时，SproutRAG使用分层束搜索在多个粒度上检索候选项，捕捉超出平面检索的多句相关性。该框架通过联合目标进行端到端训练，同时改进嵌入和树结构。跨越科学、法律和开放域设置的四项基准实验表明，SproutRAG在信息效率（IE）上平均比最强基线提高6.1%。代码可在https://github.com/AmirAbaskohi/SproutRAG获取。

## Abstract
Retrieval-augmented generation (RAG) systems must balance retrieval granularity with contextual coherence, a challenge that existing methods address through LLM-guided chunking, single-level context expansion, or hierarchical summarization. These approaches variously depend on costly LLM calls during indexing or retrieval, limit context aggregation to a single granularity level, or introduce information loss through summarization. We present SproutRAG, an attention-guided hierarchical RAG framework that addresses this trade-off by organizing sentence-level chunks into progressively larger but semantically coherent units, using learned inter-sentence attention to construct a binary chunking tree. Unlike prior approaches that rely on external LLMs, fixed context expansion, or lossy summarization, SproutRAG learns which attention heads and layers best capture semantic document structure, enabling multi-granularity retrieval without additional LLM calls or compressed summaries. At retrieval time, SproutRAG uses hierarchical beam search to retrieve candidates at multiple granularities, capturing multi-sentence relevance beyond flat retrieval. The framework is trained end-to-end with a joint objective that improves both embeddings and tree structure. Experiments across four benchmarks spanning scientific, legal, and open-domain settings demonstrate that SproutRAG improves information efficiency (IE) by 6.1% on average over the strongest baseline. Code is available on https://github.com/AmirAbaskohi/SproutRAG.

## 一、论文的核心问题与整体含义

长文档检索增强生成（RAG）面临着**检索粒度与上下文连贯性之间的根本性权衡**：粗粒度分块保留语境但引入噪声，细粒度分块精准却导致语义碎片化。现有方法或依赖昂贵的LLM调用进行分块/过滤，或将上下文聚合限制在单一层级，或通过有损摘要牺牲关键信息。  
SproutRAG 的核心目标是**在不需要额外LLM调用和损失摘要的情况下，实现高效多粒度检索**，用学习到的句间注意力构建层次化文档结构，从而在检索时同时保留精细证据和跨句连贯性。

## 二、论文提出的方法论

SproutRAG 分为离线索引和在线检索两个阶段，整体通过端到端训练优化。

### 2.1 核心思想
- 将文档切分为句子级单元（chunks），利用小型语言模型（SLLM）得到句子嵌入和注意力矩阵。
- **学习头–层权重聚合**代替简单平均，缓解位置偏差，发现最能体现语义相关的注意力头。
- 基于聚合后的互注意力得分，**自底向上构建二叉分块树**，叶子节点为句子，内部节点存储渐进式嵌入（子节点均值），且继承最大互注意力维持长程连接。
- 检索时采用**分层束搜索**，从根节点出发，在每个深度扩展子节点并保留 top-b 节点，同时收集所有遍历中相似度超过阈值的节点，最终重排序后送入生成器。

### 2.2 关键技术细节与公式

1. **注意力聚合**  
   对每一层 `l` 和每一头 `h` 的注意力矩阵 `Attn^(l,h)`，引入可学习标量 `α_{l,h}`，计算加权注意力：
   ```
   A_ij = Σ_l Σ_h w_{l,h} Attn^(l,h)_ij
   ```
   其中权重 `w_{l,h} = exp(α_{l,h}) / Σ_{l',h'} exp(α_{l',h'})`。  
   然后对称化得到互注意力 `M_ij = (A_ij + A_ji)/2`。

2. **树构建**  
   初始化每个句子为一个叶子节点。重复合并当前互注意力最高的一对节点，新父节点嵌入为子节点均值 `e(p) = (e(u)+e(v))/2`，并更新其余节点与新父节点的关系为 `M_pr = max(M_ur, M_vr)`（单链接），直至只剩根节点。

3. **分层束搜索检索**  
   给定查询嵌入 `e(q)`，节点相似度 `sim(q,v) = e(q)^T e(v) / (||e(q)|| ||e(v)||)`。  
   从根节点开始，在第 `t` 层当前束 `B_t`，扩展子节点并保留相似度最高的 `b` 个作为 `B_{t+1}`。同时收集所有扩展中相似度超过阈值 `δ` 的节点形成候选集 `C`。最后对候选集进行相似度重排序，取 top-k 证据单元。

4. **联合训练目标**  
   - 检索损失 `L_ret`：使用对比学习，以均值池化后的句子嵌入代表段落，拉近查询与正例、推远负例。  
   - 结构损失 `L_attn`：鼓励正例段落内共同支持查询的句子对获得高互注意力。  
   - 最终损失 `L = L_ret + λ L_attn`，端到端微调 SLLM 和注意力聚合参数。

## 六、论文的主要结论与发现

1. **检索性能显著提升**：SproutRAG 在四个检索基准上的 IE 均优于所有对比方法，平均超出最强基线 6.1%，且同时实现了最高的精确率和召回率提升。  
2. **层次树与注意力学习至关重要**：学习到的头–层聚合有效抑制位置偏差，比均匀聚合或嵌入相似度建树更优；分层束搜索结合内部节点检索比仅用叶节点或贪婪搜索效果更好。  
3. **联合训练不可或缺**：检索损失和结构损失共同作用，单独移除任一项都会导致 IE 下降。  
4. **效率优势**：在生成任务上超越了 GraphRAG、ReflectiveRAG 等系统，且在线 token 消耗和延迟远低于需要 LLM 推理或反思的方法，实现“性能–效率”的良好平衡。  
5. **泛化能力**：一次性训练的树结构可在不同数据集上直接使用，无需重新训练。

## 七、优点

- **创新性强**：首次将学习到的句间注意力直接用于构建检索导向的文档层次树，避免了 LLM 调用和摘要损失。  
- **多粒度无缝覆盖**：叶子、内部节点均可被检索，既能获取精确句子也能捕捉跨句语义单元。  
- **端到端可训练**：联合优化嵌入和树结构，且训练开销仅一次性，推理时无额外模型调用。  
- **实验设计严谨**：多领域基准、强基线对比、充分的消融分析和效率评估，结果稳健。

## 八、不足与局限

1. **树结构固定为二叉**：可能无法完美表示多句同时构成一个语义组的情况（如多分支）。  
2. **需要预训练/微调阶段**：虽一次性，但相比零样本直接使用的检索器仍有额外训练成本（3 万样本微调）。  
3. **索引静态化**：树结构在离线构建后不再随查询调整，面对需要查询特定重组证据的任务可能不够灵活。  
4. **对比覆盖**：实验中未与其他较新的动态分块或查询感知检索方法进行横向比较（如 Late Chunking 的不同变体）。  
5. **资源需求未完全详述**：尽管推理便宜，但训练 GPU 内存和整体训练时间未明确给出；仅依赖 1.3B SLLM，未探索不同规模编码器的影响。
