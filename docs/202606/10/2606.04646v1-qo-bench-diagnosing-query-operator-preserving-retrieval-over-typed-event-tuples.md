## 摘要
许多针对商业、法律和科学语料的真实世界问题，本质上是文本中潜在记录上的数据库式查询的自然语言版本。现有的检索增强生成系统主要针对语义相关性进行优化，但检索到看似合理的段落并不能保证正确的查询执行。我们引入QO-Bench，这是一个针对类型化事件元组上的查询算子问答的诊断基准。该基准覆盖了22,984篇新闻文章和614个企业事件，涉及18个查询模板，并在785个问题上进行评估。每个标准答案均由类型化事件元组确定性计算得出，并以召回率评分，答案通过精确匹配与标准元组对应，而非使用大语言模型评判。这种设计支持诸如连接和交集等算子层面的诊断。我们在匹配条件下评估了RAG、ReAct RAG、GraphRAG和从信息抽取到SQL的方法，并设置了一个长上下文上界来隔离检索失败。一个双轴框架——索引时保留与查询时执行——预测了每种范式在何处失败，结果也印证了这一点：系统检索到相关文本，却丢弃了算子所需的类型化值，且可部署范式的排名在不同算子上反转：相似性检索在过滤和投影上领先，而从抽取到SQL在交集和计数上占优。即使给定标准证据，长上下文上界仍远未饱和，因此算子执行——而非仅仅是检索——是一个核心瓶颈，更强的答案模型也无法消除它。QO-Bench将目标从段落相关性重新定义为查询算子保留检索。

## Abstract
Many real-world questions over business, legal, and scientific corpora are natural-language versions of database-style queries over records latent in text. Existing retrieval-augmented generation (RAG) systems are optimized primarily for semantic relevance, but retrieving plausible passages does not guarantee correct query execution. We introduce QO-Bench, a diagnostic benchmark for query-operator question answering over typed event tuples. The benchmark covers 22,984 news articles and 614 corporate events across 18 query templates, evaluated on 785 questions. Each gold answer is deterministically computed from typed event tuples and scored by recall, with answers matched to the gold tuples by exact match rather than an LLM judge. This design enables operator-level diagnosis such as joins and intersection. We evaluate RAG, ReAct RAG, GraphRAG, and information-extraction-to-SQL under matched conditions, with a long-context oracle ceiling to isolate retrieval failure. A two-axis framework -- index-time preservation versus query-time execution -- predicts where each paradigm fails, and the results bear it out: systems retrieve relevant text but discard the typed values operators need, and the deployable paradigm ranking inverts across operators, with similarity retrieval leading on filter/project and extraction-to-SQL on intersection and counting. Even given the gold evidence, a long-context oracle stays far from saturated, so operator execution -- not retrieval alone -- is a core bottleneck that a stronger answer model does not remove. QO-Bench reframes the goal from passage relevance to query-operator-preserving retrieval.

- **研究目标**：提出“查询算子保留检索”（query-operator-preserving retrieval）概念，强调检索不仅要返回语义相关文本，更需保留执行算子所需的类型化值（如实体名、角色、日期）。论文通过构建诊断基准QO-Bench，系统量化不同检索架构在“查询算子问答”（QO-QA）场景下的失败模式，明确瓶颈所在。

### 6. 论文的主要结论与发现

- **无系统在所有算子上占优**：可部署范式的排名在不同算子家族间反转。相似性检索（RAG、ReAct）在过滤/投影上占优（53.6%/55.4%），但IE→SQL在交集（50.9% vs. RAG 6.0%/ReAct 9.5%）和计数/分组（51.2% vs. ReAct 3.4%）上显著领先。
- **算子执行是核心瓶颈**：即使给定标准证据，LC-oracle整体召回仅52.2%，在交集上仅3.9%，且更强的答案模型无法改善。这表明LLM自由生成难以可靠执行集合交集等操作，架构不匹配。
- **失败模式符合双轴预测**：
  - 相似性检索因固定Top-k导致覆盖率不足（Cap B覆盖率仅27-30%），丢失需要组合的证据。
  - GraphRAG虽保有结构，但社区摘要压缩了精确值（角色、日期、计数），导致值保真度丧失。
  - IE→SQL面临模式僵化问题：跨事件连接（如公告→完成）因缺少连接键而失败。
- **框架指导**：索引时保留和查询时执行两个维度的失败清晰分离，表明需要同时实现宽覆盖和灵活的类型化执行。

### 7. 优点

- **确定性评估**：基于类型化事件元组的标准答案和精确匹配，消除了LLM评判的主观性，使失败可归因到具体算子。
- **算子级诊断**：18个模板精心设计，覆盖过滤、连接、交集、聚合等核心算子，能够定位每种架构的脆弱点。
- **公平对比**：所有系统共享语料、事件定义、答案模型和事件定义提示，仅检索架构不同，确保对比归因于架构差异。
- **双轴分析框架**：清晰将失败分解为索引保留（覆盖、值保真度）和查询执行，为未来系统设计提供可操作的指引。
- **保守上限**：长上下文上界隔离检索失败，并直接揭示答案模型不能解决的算子执行瓶颈。

### 8. 不足与局限

- **领域局限性**：基准仅覆盖金融新闻与8种公开企业事件，绝对性能可能无法直接迁移到其他领域（如法律、生物医学），特别是实体消歧和事件模式较弱的环境。
- **查询多样性不足**：问题由模板生成，虽然控制了个算子探针，但未充分代表真实用户问题中语言表达的丰富性和复杂性。
- **评估简化**：仅考虑单文档可证实事件，避免了多文档拼接证据的挑战，因此发现的失败模式可能低估了真实多文档检索的难度。
- **答案格式限制**：要求系统返回结构化答案（列表、计数等），未评估非结构化自由文本回答，可能限制了对生成式范式的全面评估。
- **提取管道依赖**：IE→SQL依赖事件抽取质量，其模式冻结且无人工修正，可能在某些模板下表现略低，但也正是为了公平测试架构性限制。
- **覆盖和标注偏置**：事件标注依赖于3位LLM裁判的一致性，虽经人工验证，但M&A完成等边界类型精度较低（73.3%），可能引入少量噪声。同时，新闻语料偏重大型上市公司和英语媒体。
