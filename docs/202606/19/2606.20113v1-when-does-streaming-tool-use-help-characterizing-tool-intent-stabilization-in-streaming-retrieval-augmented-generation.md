## 摘要
流式检索增强生成（流式RAG）通过在用户输入未完成时并行发出工具查询，来减少用户感知的延迟。报告中的增益是聚合的，但该机制的益处从根本上说是查询内在的：只有当正确的工具查询在用户停止说话或打字之前变得可确定时，推测才能提供帮助。我们分离并度量了这一特性——工具意图稳定化，即输入流中推测性查询的检索收敛到包含答案的结果的那个时间点。在CRAG基准（1371个验证问题）上，我们（i）测量了稳定化的分布，（ii）推导出一个与模型无关的界限H，表示可隐藏于用户剩余输入背后的工具延迟部分，作为工具延迟L和输入节奏δ的函数，（iii）在一个可工作的流式流水线上进行验证，证实现实的节省达到或超过了此界限，以及（iv）识别哪些查询属性能够预测早期与晚期稳定化。该研究无需模型训练，可在普通CPU硬件上运行。我们发现，在一个现实操作点（L=600ms，δ=3词/秒，θ=0.8）下，整个基准中73.9%的查询能够实现显著的延迟隐藏——这是一个混合数字，结合了21.3%的问题上的充分稳定化（其中金标准证据逐字存在且BM25可检索，且在有利子集上95.2%可流式化）与其余问题上的无依据的top-1稳定回退。在有利子集上，φ_suf被精确和宽松依据约束在[0.26, 0.281]之间——两者都很早。问题类型产生了显著但粗略的早期/晚期划分（Kruskal-Wallis p=0.017，ε²=0.04），直接指示了学习到的推测触发器何时值得其成本。

## Abstract
Streaming Retrieval-Augmented Generation (Streaming RAG) reduces user-perceived latency by issuing tool queries in parallel with ongoing user input, before the utterance is complete. Reported gains are aggregate, yet the mechanism's benefit is fundamentally query-intrinsic: speculation can only help when the correct tool query becomes determinable before the user stops speaking or typing. We isolate and measure this property -- tool-intent stabilization, the point in the input stream at which a speculative query's retrieval converges to the answer-bearing result. On the CRAG benchmark (1371 validation questions) we (i) measure the distribution of stabilization, (ii) derive a model-agnostic bound H on the portion of tool latency that can be hidden behind the user's remaining input, as a function of tool latency L and input cadence δ, (iii) validate against a working streaming pipeline that realized savings meet or exceed this bound, and (iv) identify which query properties predict early versus late stabilization. The study requires no model training and runs on commodity CPU hardware. We find that at a realistic operating point (L=600ms, δ=3w/s, θ=0.8), 73.9% of queries across the full benchmark admit substantial latency hiding -- a blended figure that mixes sufficiency stabilization on the 21.3% of questions where gold evidence is verbatim-present and BM25-retrievable (95.2% streamable on this favorable slice) with a grounding-free top-1-settling fallback on the remainder. On the favorable slice, φ_suf is bracketed to [0.26, 0.281] by exact and relaxed grounding -- both early. Question type produces a significant but coarse early/late split (Kruskal-Wallis p=0.017, epsilon^2=0.04), directly informing when a learned speculative trigger is worth its cost.

## 1. 论文的核心问题与整体含义
- **核心问题**：流式检索增强生成（Streaming RAG）通过在用户输入完成前并行发起工具调用（如搜索请求）来隐藏延迟，但其有效性本质取决于一个关键前提——**正确的工具查询能否在用户说完或打完字之前被确定**。目前的研究仅报告聚合层面的延迟收益，并未分析这一前提在单个查询上的表现。
- **研究动机**：需要量化「工具意图稳定化」（tool‑intent stabilization）这一内在特性，即输入流中推测查询的检索结果何时收敛到真正有用的信息，从而为判断何时发起推测、能隐藏多少延迟提供明确上界。
- **整体含义**：论文将工具意图稳定化作为一个可测量的、与具体模型无关的量，为流式工具使用的触发设计提供理论依据，并回答“对于哪些查询推测有帮助、帮助多大”这一根本问题。

## 2. 方法论
- **核心概念与定义**  
  - **自恰稳定化（Self‑consistency，\(t_{sc}\)）**：最小前缀长度 \(t\)，使得从该前缀起，top‑1 检索文档始终与完整查询的 top‑1 一致。  
  - **充分稳定化（Sufficiency，\(t_{suf}\)）**：最小前缀长度 \(t\)，使得金标准文档 \(d^*\) 首次出现在 top‑k 结果中。  
  - **稳定化比例** \(\phi = t^*/n\)（\(n\) 为查询总词数），数值越小代表稳定化越早。  
  - **易变性** \(V\)：记录 top‑1 结果首次达到 \(d_n\) 后再发生变化的次数，用于评估早期提交风险。
- **延迟隐藏上界**  
  \[
  H(Q; L, \delta) = \min\left(L,\;\max\left(0,\;\frac{n - t^*}{\delta}\right)\right)
  \]  
  其中 \(L\) 为工具调用延迟（毫秒），\(\delta\) 为输入节奏（词/秒）。只有当 \(H \ge \theta L\)（\(\theta\) 为覆盖阈值）时该查询才被视为「可流式化」。
- **分析流程**  
  - 使用纯 Python BM25 检索器（\(k_1=1.5,\;b=0.75\)），对每个查询的所有前缀进行检索，记录 top‑k 结果。  
  - 通过字符串匹配从网页文本中标注金标准答案所在文档（既采用精确子串匹配，也采用宽松的“词袋内容包含”作为稳健性检查）。  
  - 在 \(L,\delta,\theta\) 的三维网格上计算可流式化比例，并搭建异步流式 RAG 验证管线（含触发器、并行线程和反射器），对比实际延迟节省与 \(H\) 界限。

## 3. 实验设计
- **数据集**：CRAG（Comprehensive RAG Benchmark）Task 1 & 2 验证集，共 1371 个问题。每个问题附带最多 5 个检索网页、金标准答案及问题类型标签。
- **基准与对比**  
  - 无传统意义上的多种方法对比；主要测量稳定化分布本身，并验证其与流水线实际表现的一致性。  
  - 流水线参考 Arora et al. (2025) 的流式 RAG 组件（查询生成约 590 ms，融合/反射约 2520 ms），加上可变工具延迟 \(L\)。  
  - 进行了 top‑k 鲁棒性扫描（\(k=1,3,5\)）和不同输入节奏下的可流式化比例对比。
- **评估指标**：稳定化比例 \(\phi\)、可流式化比例（在不同 \(L,\delta,\theta\) 下）、实际延迟节省与 \(H\) 的偏差、问题类型对 \(\phi\) 的效应。

## 4. 资源与算力
- **算力需求极低**：论文明确声明无需任何模型训练，所有实验均在消费级 CPU 上完成，无需 GPU。
- 未提及具体硬件配置，也未涉及训练时长。

## 5. 实验数量与充分性
- **实验组次丰富**：  
  - 对全部 1371 个查询测量了两种稳定化分布。  
  - 在 \(L\in{100,300,600,1000}\) ms、\(\delta\in{2,3,4}\) 词/秒、\(\theta\in{0.5,0.8,1.0}\) 的 36 个组合下计算可流式化比例。  
  - 在 60 个可检索到金标准证据的查询上重放流水线，对比 \(L=600\) ms 和 \(1000\) ms 两种设定。  
  - 问题类型分析覆盖 8 类，并进行 Kruskal–Wallis 检验与 Dunn 事后检验。  
  - 稳健性检验包括宽松依据条件、top‑k 敏感性、失误率分析。
- **客观性与充分性**：实验设计围绕预注册研究问题展开，既有统计检验又有界限验证，整体比较充分。但验证流水线的查询样本较小（60 个），且金标准标注仅基于字符串匹配，可能引入偏差，作者已通过宽松匹配和限定条件说明来减轻影响。

## 6. 主要结论与发现
- **稳定化现象显著不对称**：充分稳定化（金标准可检索）很早就发生（均值 \(\phi_{suf} \approx 0.26\)，被宽松条件限定在 \([0.26,0.281]\)），而自恰稳定化（top‑1 不再变动）则偏晚（均值 \(\phi_{sc} \approx 0.67\)）。这说明答案所需的文档往往远在查询词序稳定前就已可检索到。
- **延迟隐藏潜力可观**：在典型工作点（\(L=600\) ms, \(\delta=3\) 词/秒, \(\theta=0.8\)）下，全基准 73.9% 的查询可隐藏至少 80% 的工具延迟；其中包含金标准证据的子集中该比例高达 95.2%。
- **问题类型有影响但较粗粒度**：问题类型对 \(\phi_{suf}\) 存在显著差异（Kruskal–Wallis \(p=0.017\), \(\epsilon^2=0.04\)），但其排序并非由推理复杂性决定，而是由关键实体的出现位置决定（聚合、比较类问题实体前移，反而稳定化较早）。
- **界限 H 在聚合层面保守但非单条预测器**：流水线实际节省超过 \(H\)（因额外隐藏了查询生成延迟），但单条查询的节省无法用 \(H\) 准确排序（Spearman \(\rho \approx 0.12\)），原因是均匀的查询生成重叠和难以在界限中表达的触发失误负面效应。
- **负面影响较小**：触发失误导致净节省为负的情况仅约 1.7%。

## 7. 优点
- **模型无关且无须训练**：界限 \(H\) 和稳定化度量仅依赖检索结果与金标准标注，可移植性强，且无需 GPU 资源。
- **定义清晰且具有工程指导意义**：明确区分「自恰」与「充分」两种稳定化，并给出可流式化的可直接计算的阈值，为触发器设计提供决策依据。
- **稳健性分析到位**：通过宽松依据、top‑k 扫描、失误率探查等方式承认并限制选择偏差，结论较为谨慎。
- **揭示了实体位置而非推理复杂度的主导作用**，对后续触发器设计有启发。

## 8. 不足与局限
- **数据集与检索器的单一性**：仅使用 CRAG 和 BM25，未涵盖稠密检索器；通用性有待验证。
- **输入模式简化**：假设输入为匀速的词流，未建模真实语音的变节奏、ASR 的不确定性与断词修正。
- **金标准确定依赖字符串匹配**：大量问题的答案无法在原始文档中逐字匹配（约 65% 不包含金标准文本），导致充分稳定化分析仅覆盖有利子集，虽然宽松匹配显示偏差有限，但仍丢失了非字面答案的查询场景。
- **稳定化度量粒度较粗**：top‑1 相等或 top‑k 包含不一定完全反映意图的确定性。
- **验证样本较小**：流水线验证仅用 60 个查询，且固定了触发器间隔，未能全面刻画不同触发策略下的表现。
- **未能给出单条查询的预测模型**，H 只能作为聚合上界使用，无法直接用于单次触发决策。
