## 摘要
工业电商搜索通过多分支检索阶段服务数亿商品，该阶段由手工调优并合并，缺乏联合优化。生成式检索（GR）有望将此阶段简化为单一模型，但统一化的阻碍不仅在于检索质量：倒排索引分支的转化率低于平台平均水平，却仍被保留，因为它是唯一几乎能够在数小时内注入新词而无需模型更新的分支；单一模型替代方案必须保持这种实时可编辑性。现有GR方法在结构上缺乏这种可编辑性：封闭码本方法在训练时将每个槽位固定为量化嵌入，而开放词汇方法则将新词的路由交给模型泛化。我们提出OneRetrieval，一个基于关键词对齐编码（KAE）的单一模型GR框架，它将每个标识符位置与可解释的属性词绑定，兼顾了竞争性的召回质量和倒排索引的可编辑性——据我们所知，这是首个可编辑的生成式检索方法。一种基于信息论的合并策略将18个属性类别组织为六个具有非均匀容量的码本组；每个码本中的预留槽位可在部署后绑定新词而无需重新训练；并通过四阶段微调流程联合保障质量与可编辑性。在五百万真实流量请求上，OneRetrieval达到了与最强生成基线相当的深度召回，其干预命中率比封闭码本编码高出一个数量级以上。在线实验中，替换倒排索引分支显著提升了订单量；将覆盖范围扩展到近乎整个检索阶段在保持转化率的同时提升了点击率。该系统已部署于快手，每日服务数亿页面浏览量。

## Abstract
Industrial e-commerce search serves hundreds of millions of items through a multi-branch retrieval stage fused by hand-tuned merging without joint optimization. Generative retrieval (GR) raises the prospect of collapsing this stage into a single model, yet unification is gated by more than retrieval quality: the inverted-index branch converts below the platform average yet persists because it is almost the only branch where operations can inject a new term within hours without any model update; a one-model substitute must preserve this real-time editability. Existing GR methods structurally lack it: closed-codebook methods fix each slot to a quantized embedding at training, while open-vocabulary methods leave new-term routing to model generalization. We present OneRetrieval, a one-model GR framework built on Keyword-Aligned Encoding (KAE), which ties each identifier position to an interpretable attribute word, pairing competitive recall quality with the editability of the inverted index -- to our knowledge the first editable generative retrieval method. An information-theoretic merging organizes 18 attribute categories into six codebook groups with non-uniform capacity; reserved slots in each codebook can be bound to new words after deployment without retraining; and a four-stage fine-tuning pipeline secures quality and editability jointly. On five million real-traffic requests, OneRetrieval matches the deep recall of the strongest generative baseline, with an intervention hit rate over an order of magnitude above closed-codebook encodings. Online, replacing the inverted-index branch significantly lifts order volume; extending to nearly the entire stage holds conversion while improving CTR. The system is deployed at Kuaishou, serving hundreds of millions of PVs daily.

**研究动机**
- 工业电商搜索的**多分支检索阶段**（包含倒排索引、稠密语义、协同过滤等分支）各自存在结构性缺陷，且通过手工调优合并，缺乏联合优化。
- **生成式检索（GR）** 有望将这些分支统一为单一模型，但现有方法均**无法保留倒排索引的实时可编辑性**：闭码本方法在训练时将槽位固定为量化嵌入；开放词汇方法缺乏确定性路由机制。二者都不能在数小时内注入新趋势词（如品牌、营销词）而不重新训练模型。
- **核心问题**：如何构建一个既能保证竞争性召回质量，又能像倒排索引一样支持实时参数无关编辑的生成式检索模型，从而替代整个多分支召回阶段。

### 2. 方法论核心思想与关键技术
**整体框架**
- 将检索形式化为**结构化语义标识符的自回归生成**。每个商品被编码为定长序列标识符，长度`L`，每个位置对应一个特定、可编辑的码本。
- 推理时用无约束束搜索生成Top-K标识符，再通过映射表返回商品列表。

**关键词对齐编码**
- 使用生产环境属性词典（词典含约108万属性词，18种细粒度类别），将查询与商品文本通过Aho-Corasick自动机匹配到属性词。
- 将18个属性类别通过**信息论凝聚聚类**合并为6个组（ECOM6），以最大化保留互信息、最小化条件熵。每组占据一个标识符位置。
- 当一个组内出现多个属性词时，利用**主体优先规则**和基于行为统计的后验重要性分数选择单一代表示词，再映射为标准码本代号。

**可扩展码本设计**
- **非均匀容量**：根据属性密度给三个密集组分配2048个槽位，三个轻量组分配1024个槽位。
- **四块布局**：每个码本划分为空槽（0）、聚类槽（尾词多对一）、独占槽（高频头词一对一）和**预留槽**（每个位置10个，共60个）。
- **预留槽实现实时干预**：训练时不绑定任何具体属性词；在Stage 3加入**自路由监督**，让模型学会“输入前缀含某预留代号则输出同一代号”；部署后只需更新属性词典和商品映射表，即可数小时内绑定新词并生效，无需修改模型。

**四阶段监督微调**
1. **Stage 0：属性-SID对齐** – 双向映射每个槽位与其代表的属性词，使模型内化位置-语义关联。
2. **Stage 1：内容对齐** – 查询、商品标题与对应SID之间的双向生成，以及类别预测，提供主要的检索质量来源。
3. **Stage 2：协同共现** – 引入点击/订单日志，训练查询SID到商品SID的跨SID路由，建立可编辑性的核心路由能力。
4. **Stage 3：个性化检索** – 加入用户近期搜索历史和商品交互SID序列，并包含少量预留槽自路由数据，训练最终部署策略。

- **深度召回持平最强生成基线**：OneRetrieval的HR@350与OneSearch基本持平（订单 0.5482 vs 0.5550，点击 0.6055 vs 0.6007），且大幅领先传统方法和多数生成式方法。

### 7. 优点
- **首次实现可编辑的生成式检索**：通过预留槽位与自路由监督，打破了生成式模型无法实时注入新项的局限，结构性地解决了工业关键痛点。
- **设计解耦且高效**：将检索质量与可编辑性分解到不同的微调阶段，各自优化，思路清晰。信息论驱动的属性分组和非均匀容量分配在极低成本下提升了效率。
- **工业系统验证完整**：不仅经过大规模离线基准测试，更完成在线A/B测试并成功部署到千亿级PV的生产环境，结论可靠。
- **完善的消融实验**：对码本长短、容量分配、层次编码以及训练各阶段都做了系统的剥离实验，明确了每个设计的作用。

### 8. 不足与局限
- **浅层精度不及专精基线**：MRR@350落后于OneSearch，表明在排序顶部的精准性上弱于为全流程优化的模型。
- **编辑能力仍有差距**：IAR@350（0.553）尚未完全达到倒排索引的水平（0.761），且预留槽位数量固定，可能无法适应爆发式的新词涌入。
- **依赖外部属性资源**：整个框架建立在高质量属性词典和提取流水线之上，对词典质量和领域覆盖要求高；迁移到属性体系不完善的领域会受限。
- **语言与领域单一**：仅在中文电商场景（快手）验证，跨语言、跨领域的泛化能力未经测试。
- **模型选择单一**：编码器-解码器采用BART-base，未探索更大规模LLM的效果。
